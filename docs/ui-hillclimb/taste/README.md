# Taste Skill integration

This run applies [Taste Skill's app-screen workflow](https://github.com/Leonxlnx/taste-skill/blob/12af471f627f866411b4bd785b19646d3672784c/skills/taste-skill/references/app-screens.md), pinned at commit `12af471f627f866411b4bd785b19646d3672784c`. Its marketing-page rules do not apply to this workout application.

The draw offered Achromatic ledger and Editorial greeting. Achromatic ledger was selected, seed `1735525639`, with `--keep palette,type`. Training is a repeated logging task, so quiet chrome and legible set figures suit it better than a greeting-led home. There were no redraws. The existing Inter typeface and selectable theme family remain; foregrounds are strengthened for legibility.

The product's visual identity comes from its actual workout prescription, entered set values, rest intervals, and completion feedback. Its blue-gray ground and blue data marks remain recognizable. No decorative metrics, stock illustrations, landing-page hero, or invented progress figures are added. The fictional Everyday Strength routine and Alex Morgan profile exist only in isolated documentation capture contexts, not in the runtime app's user data.

## Screen questions

| Screen | Main question and next action |
| --- | --- |
| Today | What do I train next, or how do I create my first routine? |
| Routines | Which routine do I open or activate? |
| Routine | Which workout do I start, with analysis available when needed? |
| Workout | What is prescribed, what did I perform, and what set comes next? |
| History | What have I done for this movement, and what can I export? |
| Profile | What goals and constraints shape my training, and how is it progressing? |
| Prompts | What do I copy into my external AI conversation? |
| Import | Is this routine valid and ready to save, and what needs resolving? |
| Library | Which exercise or concrete version am I looking for? |
| Workspace | How do I protect my data and adjust this device's appearance? |

The direction sheet is retained in [direction.json](direction.json). Browser inspection results and exceptions belong in the round reports. The independent scoring rubric and acceptance gate stay fixed so adopting this skill does not change the definition of a passing score.
